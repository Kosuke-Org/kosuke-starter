# AGENTS.md

How this app is built and where things go. Read it before changing code.

## What it is

One Cloudflare Worker serves the API and the React app on one port.

- **Client:** React 19, Vite 8, TanStack Router (file routes), TanStack Query, Tailwind 4, shadcn/ui.
- **Server:** Hono on Cloudflare Workers (`worker/`).
- **Database:** Cloudflare D1 (SQLite) through Drizzle. Locally, Wrangler keeps a SQLite file in `.wrangler/`.
- **Auth:** Better Auth, email and password, stored in D1. Wired, but no route requires it yet.

`bun run dev` starts Vite with `@cloudflare/vite-plugin`, so the Worker runs in `workerd`, the same runtime as production. What works in dev works when published.

**Dev memory budget: about 900 MB** for the whole dev process tree (Vite plus `workerd`). Measured at 774 to 871 MB in a 2 vCPU / 4 GB sandbox. Most of it is `@cloudflare/vite-plugin` running the Worker in `workerd` inside Vite, which is kept on purpose so dev and production share one runtime. A change that pushes the idle tree past 900 MB needs a reason.

## Commands

| Command | What it does |
|---|---|
| `bun install` | Installs, and creates `.dev.vars` with a random auth secret if missing |
| `bun run dev` | Applies local migrations, then starts the dev server |
| `bun run typecheck` | `tsc -b` over the client, the Worker, the tests and the configs |
| `bun run lint` | ESLint, zero warnings allowed |
| `bun run test` | Vitest smoke test against the real Worker and a local D1 |
| `bun run build` | Production build into `dist/` |
| `bun run db:generate` | Writes a SQL migration in `migrations/` from `worker/db/schema.ts` |
| `bun run db:migrate` | Applies migrations to the local database |
| `bun run deploy` | Builds, applies migrations to the production D1, deploys the Worker |

Run `typecheck`, `lint` and `test` before you say a change is done.

## Where things go

```
src/                      the React app
  main.tsx                router + query client
  routes/                 one file per page (TanStack file routes)
  components/             app components
  components/ui/          vendored shadcn/ui, edit only to change the design system
  hooks/                  React hooks
  lib/api.ts              typed client for the Worker (hono/client)
  lib/auth-client.ts      Better Auth client: useSession, signIn, signUp, signOut
worker/                   the Cloudflare Worker
  index.ts                the Hono app; every route is mounted here
  routes/                 one file per API resource
  db/schema.ts            every table
  auth.ts                 Better Auth setup
  env.ts                  bindings and secrets the Worker receives
migrations/               SQL generated by drizzle-kit, applied by Wrangler
test/                     Vitest
.kosuke/recipes/          how to add payments, email, uploads, AI, background jobs
```

## How to add things

**A page.** Create `src/routes/<path>.tsx` exporting `Route = createFileRoute("/<path>")({ component })`. The dev server regenerates `src/routeTree.gen.ts`; commit it.

**An API route.** Create `worker/routes/<name>.ts` as `new Hono<AppEnv>()` with chained handlers, and mount it in `worker/index.ts` with `.route("/api/<name>", <name>)`. Keep the chain: the client's types come from it. Validate input with `validator` from `hono/validator`. Call it from the client as `api.api.<name>.$get()`.

**A table.** Add it to `worker/db/schema.ts`, run `bun run db:generate`, then `bun run db:migrate`. Never edit a migration that has been applied; write a new one.

**A signed-in-only route.** In the handler:

```ts
const session = await createAuth(c.env, new URL(c.req.url).origin).api.getSession({ headers: c.req.raw.headers });
if (!session) return c.json({ error: "Sign in first" }, 401);
```

On the client, read `useSession()` and redirect to `/sign-in` when there is no session.

**A cookie.** A published app shares its parent domain with other people's apps, so any of them can set a cookie that this app receives. Name every cookie the app sets with the `__Host-` prefix and set it with `Secure`, `Path=/` and no `Domain`: the browser then refuses to let another subdomain set or overwrite it. Better Auth already does this over https (`worker/auth.ts`). Never set `Domain` on a cookie, and never turn on Better Auth's `crossSubDomainCookies`.

**A secret.** Add it to `worker/env.ts` and `.dev.vars.example`, put the real value in `.dev.vars` locally. In production it is a Worker secret, set by Kosuke.

**UI.** Compose from `src/components/ui/`, and do not install another UI library. Colours come from the theme tokens in `src/index.css`, so both dark and light work.

The starter vendors the shadcn components most apps use: accordion, alert, alert-dialog, avatar, badge, breadcrumb, button, card, checkbox, collapsible, dialog, dropdown-menu, empty, field, input, input-group, kbd, label, pagination, popover, progress, radio-group, scroll-area, select, separator, sheet, sidebar, skeleton, slider, sonner, spinner, switch, table, tabs, textarea, toggle, toggle-group, tooltip.

Any other shadcn component is one command away. The pinned `shadcn` dev dependency writes it into `src/components/ui/` and installs its package:

```sh
bunx shadcn add <component>
```

For example `calendar`, `command`, `carousel`, `drawer`, `input-otp`, `resizable` or `combobox`. They were left out because each brings its own package (react-day-picker, cmdk, embla-carousel-react, vaul, input-otp, react-resizable-panels, @base-ui/react). Add one only when the app needs it.

## Rules

- **Server code runs on Cloudflare Workers.** No Node or Bun APIs in `worker/` (`fs`, `path`, `process`, `Buffer`, `Bun.*`). Use Web APIs: `fetch`, `crypto.subtle`, `TextEncoder`, `Uint8Array`. Lint enforces the common ones. Bun is only the package manager and script runner here.
- **D1 has no interactive transactions.** Writes that must succeed or fail together go in one `db.batch([...])`. Do not use `db.transaction()`.
- **Read bindings and secrets from `c.env`**, never from globals. A Worker gets them per request.
- **One schema file, generated migrations.** The schema is the source of truth; `migrations/` is generated from it.
- **Keep dependencies few.** Prefer what is already installed. For payments, email, uploads, AI or background jobs, follow `.kosuke/recipes/`.
